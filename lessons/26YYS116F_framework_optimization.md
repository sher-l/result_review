# 26YYS116F 可复用框架优化镜像

> 本文只镜像本项目仲裁中的耐久教训；不代表已对框架文件实施修改。

## 建议收紧的检查

- 项目来源隔离（ARB-001、002）：对高风险模块同时扫描路径、父目录、日志与运行元数据；出现外项目编号时，要求当前项目输入和运行链闭合后才可归属。
- 交付可复现性（ARB-010、013、014、019）：以“输入—参数/脚本—运行记录—结果/轨迹”四层验收；核心输入或路径缺失是独立重跑阻断，单纯无代码仍按 WARNING。
- 方法一致性（ARB-004、005、006、011、012）：报告方法的阈值、开关、GMT、方法名须对应脚本参数、调用及产物，输出三方差异表。
- 机器学习证据链（ARB-003、016）：将特征选择、训练、阈值、外部验证、不确定性独立核验；单点 AUC 不等于无偏全流程验证。
- MR 统计规则（ARB-006、011、017）：过滤条件必须实际执行并留痕，方法须有调用/产物，多重检验须有检验族与校正表。
- 二级分析（ARB-015、018）：对接实行 rank-1—pose—汇总表核对；MD 的绝对稳定性表述须有重复、收敛和自由能证据。
- 文本与结构（ARB-007、008、009、020）：以项目配置生成疾病/基因/目录词表，全文扫描模板残留、近似符号和路径映射；最终检查章节连续性。

## 无需收紧为自动升级的边界

- 缺少完整对接执行链（ARB-013）本身保留 WARNING，不能自动推断数据来源污染。
- eQTL F/MAF 过滤未实现（ARB-006）要求代码和筛选日志修复，但不据此认定弱工具变量已进入结果。
- 结果归档路径偏离脚本约定（ARB-009）要求迁移映射，不默认认定外项目污染。
- 章节编号缺失（ARB-020）应由既有格式门禁拦截，属于执行强化而非新政策需求。
