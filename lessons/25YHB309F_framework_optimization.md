# 25YHB309F 审核框架优化笔记

## 结论

本项目暴露的主要框架缺口不是“缺少更多目录存在性检查”，而是**项目边界、跨模块数据流、可复现性交付和低收敛仲裁的联动不足**。下列为应加严的政策、检查和子任务提示；本文件仅提出优化建议，不修改框架或项目源文件。

## 子任务提示应如何更新

### 1. 代码与溯源子任务

新增硬性提问：

1. 当前项目编号、项目根目录及允许共享资源清单是什么？
2. 代码中的每个绝对路径、外部项目编号和输入对象是否在清单内？
3. 是否存在代码“可打开但运行时读取外部项目对象”的情况？给出文件和行号。

禁止以“仅一处脚本”或“目录内存在结果”为由降低项目边界问题等级。

### 2. 机器学习与统计子任务

新增最小核对顺序：

1. 从原始结果表重算报告中的关键 AUC/均值；
2. 比较最小类别样本数与 CV 折数；
3. 比较声明模型数与结果矩阵行数；
4. 建立报告数据集名、样本 ID、训练/验证列名的映射；
5. 核对 DEG 的 `pvalue/padj` 阈值，并标示所有下游消费链。

输出应区分“数值矛盾”“设计不可行”“来源不可追溯”“输出不足”，不得将其压缩为一个笼统的 ML 问题。

### 3. 视觉与高风险模块子任务

新增硬性提问：

1. 图轴、图例和面板数是否支持图注与正文的变量/方向主张？
2. 对接、MD、拟时序、CellChat、虚拟敲除各自的最小结构化交付物是否齐备？
3. 结论是描述性观察，还是声称稳定性、因果性、平衡或泛化性？对应证据是否足够？

输出中必须将“模块存在”“可审计”“可复现”“结论不过度”分栏记录。

### 4. 收敛与仲裁子任务

新增硬性提问：

1. `converged`、共识率、多数率、单路率分别是多少？
2. 所有单路 CRITICAL/MAJOR 是否已进入队列？若没有，排除理由是什么？
3. 多路相似发现是同一事实还是仅同一模块？请以对象—断言—证据—失效机制判定。

仲裁完成条件应包括“候选守恒核验”，而不是仅检查 JSON 队列是否为空。

## 可复用的既有模式：应引用，不重复造规则

下列既有 lessons 已覆盖基础模式，应在相应检查中引用并补充上述更严格的执行层，而非创建相互矛盾的重复规则：

- `lessons/patterns/copy_paste_residue.md` 的 P01/P03：项目编号、路径和数据集残留；本项目应补足“运行时输入路径”与 CRITICAL 路由。
- `lessons/patterns/data_flow_coverage.md` 的 P06/P11：数据流断裂与双向覆盖；本项目应补足 FDR 状态向下游 ML 的传播。
- `lessons/patterns/figure_visual_errors.md` 的 P08：图号、图注和视觉错误；本项目应补足图轴—图注—正文的变量语义核对。

## 无需变更的项

1. **不应把缺少脚本/日志直接定性为算法一定错误。** 现有“证据不足/不可复现”与“结论错误”分离的原则应保持；本项目的处理亦仅在有直接数值或图文冲突时认定具体断言不成立。
2. **不应因高风险目录存在而自动放行。** 现有目录清点仍有价值，但只能作为存在性证据，不能替代新增的可审计与可复现检查。
3. **不应把自动文本相似度当作事实合并结论。** 现有人工（仲裁）拆分、合并与降重思路应保持；需要加强的是字段化合并理由和候选守恒校验，而非依赖更激进的自动合并。
4. **不应仅因单路发现而自动升级严重度。** 单路发现仍需有可定位证据；本项目仅对证据直接、影响关键链条的事项保留相应等级。

## 建议的验证用例（供后续框架维护时使用）

- 含外部项目 `setwd` + `qread` 的最小 R 脚本：应触发项目边界 CRITICAL 候选。
- 30/7 类别、10 折 CV、113 声明模型、100 行 AUC 的最小结果包：应分别触发 CV、模型数和 AUC 规则。
- 图注称“基因—基因集”，图轴实际为 CytoTRACE 的图文对：应触发语义错配，而非只报告编号错误。
- `converged=false`、高单路率、空仲裁队列的模拟收敛输出：应自动生成待裁决项并阻止“无问题”结论。
- 仅有 PDF/XVG、无参数/轨迹/日志的 MD 包：应标为“存在但不可复现”，不得断言模拟本身错误。
