# 26YSH093F：网络毒理学来源与高风险计算可追溯性

> 项目可追溯来源：`result_review_report/26YSH093F/agent_results/arbitration/arbitration_resolution.json`（F-001、F-004、F-008 至 F-014）与 `result_review_report/26YSH093F/visual_audit_result.json`。本条为可复用审核模式，不替代其他项目的独立核验。

## 可复用规则

1. 多数据库靶点表必须把每一列闭合到原始输入、代码读取变量、处理输出和报告计数。数据库名称、节点上限、物种或置信度只要有一项与代码/计数冲突，就不能把汇总计数当作已验证来源。
2. 报告中每个字段筛选条件应成为可逐项定位的代码谓词或上游预筛选证明。输入表包含该字段而代码未使用，是优先复核信号。
3. 富集分析的“校正后显著”需明确校正方法、对象和实际字段；top-K 必须在报告、代码、图中条目数和下游网络输入四处一致。
4. 对接与 MD 的展示性文件不等于可重放证据。对接需原始评分、任务输入、腔体/搜索参数、日志；MD 需报告版本与原始元数据一致，并提供体系输入、轨迹和运行/分析命令或等价归档。
5. 多面板图的审计定位以图片占位、图号、面板和资产 ID 的显式绑定为准；视觉复核还须逐图核对统计单位、图例和正文解释层级。

## 触发提示

- 报告的数据库分项计数出现来源列互换、超过自述节点上限，或无法由代码注释/原始输出复算。
- `slice_head(n=...)`、排序字段或下游网络截取与正文/图注的 top-N 声称不同。
- GROMACS/对接工具版本只存在于正文，或原始 XVG/日志显示另一版本。
- 图像资产清单按临近图注而非实际图片占位绑定，或统计图颜色语义只在正文出现。

## 审核边界

无脚本/代码本身不能自动升格为高严重度；应把结果存在性、最小证据包完整性、方法—代码一致性和结论强度分别判定。
