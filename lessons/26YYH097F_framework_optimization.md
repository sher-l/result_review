# 26YYH097F 可复用框架经验

## 适用范围与去重说明

本文件镜像 26YYH097F 的耐久经验，不复制项目最终报告，也不改变其 `leader_confirmed` 仲裁（50/100、BLOCK）。仓库已有 QC 单调性、细胞类型翻译、验证泄漏及 docking/MD/虚拟筛选证据链 lesson；因此本文件只记录本项目带来的执行强化与跨模块组合规则。未另建独立 `26YYH097F_scrna_identity_and_qc_lesson.md`，以避免与 `LESSONS_LEARNED_26YYS083F.md`、`LESSONS_LEARNED_25YYF085F.md` 及 `patterns/figure_visual_errors.md` 重复。

## L1. 视觉清单必须同时闭合“已审、跳过、不支持”

- **错误类型：** 视觉审核覆盖虚高 / 资产对账缺失。
- **具体表现：** 预筛清单有 74 个 raster，但磁盘实际有 108 个视觉资产；34 个 EMF 未入清单。若只写“10 必审 + 64 跳过”，会误让读者以为 108 个资产均已覆盖。
- **触发场景：** 报告解包后包含多种图片格式，预筛工具只支持部分格式；审核完成判断只看文件存在或 TODO。
- **证据依据：** 26YYH097F 的 74 个 manifest 条目、10/10 必审、64/64 standard-lane 跳过，以及 34 个清单外 EMF。
- **正确标准：** 全部资产必须唯一落入 `human_reviewed`、`policy_skipped`、`unsupported` 三类；满足 `asset_total = reviewed + skipped + unsupported`，同时 manifest 内满足 `manifest_total = reviewed + skipped`。
- **下次审核提醒：** 先数磁盘资产，再数预筛 manifest；任何差额都必须按格式和原因列出，不得并入“已跳过”或“已通过”。
- **严重程度：** 框架 P0；项目 finding 严重度仍由被漏资产的实际风险决定。
- **可执行规则建议：** 预筛 JSON 固定输出总资产、支持格式、未支持格式及未解释资产；finalize 前执行集合差分并 fail closed。

## L2. “0 machine flag”不是视觉通过，图内事实与图外映射须分层

- **错误类型：** 机器预筛过度信赖 / 证据来源混淆。
- **具体表现：** 26YYH097F 的 74 张图均无 flag，但 OCR 全部不可用；细胞身份错译和 docking 图缺少对象/评分自证仍由人工发现。外部题注能把图片映射到特定蛋白—配体，不等于图内包含这些信息。
- **触发场景：** OCR 失败、图中标签细小、图像依赖题注/文件名/正文才能识别对象，或高风险图未命中通用图像 flag。
- **证据依据：** `image_037.png` 的英文细胞标签；`image_049.png`、`050`、`051`、`085` 未在图内嵌入蛋白、配体或 score；CF-013、CF-017。
- **正确标准：** 逐图分开记录 `visible_in_figure`、`mapped_from_caption_or_context`、`not_proven_by_figure`；高风险图按业务风险必审，不以 0 flag 免审。
- **下次审核提醒：** 当 OCR 不可用时显式声明降级；“图可打开”只证明可渲染，不证明标签、身份、统计或结论正确。
- **严重程度：** 框架 P1；具体项目按语义错误和证据缺口分别定级。
- **可执行规则建议：** B02 输出 schema 加入三层证据字段及 OCR 状态；自证要求未满足时生成可追踪 finding 或边界说明。

## L3. 单细胞翻译与 QC 单调性应从经验升级为硬检查

- **错误类型：** 生物学身份错译 + 流程不变量违反。
- **具体表现：** pDC、Plasma cells、B cells 等免疫细胞被译成脑/肿瘤语境名称；质控后细胞数 197202 高于质控前 181393。
- **触发场景：** 中英文标签转换、模板复用、跨疾病语境改写，以及单细胞过滤前后统计汇总。
- **证据依据：** `image_037.png` 与报告译名冲突（CF-013）；报告质控前后计数及 `image_030.png` 的 After Quality Control 语境（CF-014）。
- **正确标准：** 细胞身份按“英文原标签—marker—中文标准名—疾病语境”四联核对；常规过滤流程要求 `after_qc <= before_qc`，反增时必须给出合并、补样本、去重口径变化等可审计解释。
- **下次审核提醒：** 不要从相似词或疾病模板猜译；图像若不显示全局计数，只能辅助定位，不能替代前后计数证据。
- **严重程度：** 对身份体系被整体改写或 QC 反增且无解释，维持 CRITICAL 硬触发。
- **可执行规则建议：** 复用既有 translation dictionary 和 QC monotonicity lesson；增加上下文四联校验和结构化计数断言，不新建平行规范。

## L4. 方法—代码一致性必须核到实现和参数层

- **错误类型：** 方法名称、统计阈值与实际实现漂移。
- **具体表现：** 报告写 GSVA `P<0.05`，代码实际使用 BH 校正且 `|t|>2`；报告写 CIBERSORTx，代码是 CIBERSORT 且 `perm=0`；LogNormalize 原理被错误描述。
- **触发场景：** 报告由模板或二次改写生成，代码只被确认“存在”，未核函数、包、参数和推断机制。
- **证据依据：** CF-018、CF-019、CF-020。
- **正确标准：** 对每个核心方法建立“报告名称/版本—代码包/函数—关键参数—阈值—多重校正—置换/随机策略—差异”矩阵；名称相似不能替代实现一致。
- **下次审核提醒：** 看到方法名后必须追到调用语句和参数；`perm=0` 等参数会改变可做的统计推断，不能当成可忽略细节。
- **严重程度：** 框架 P0；项目层按对结论的影响定级。
- **可执行规则建议：** C01 固定输出矩阵，对方法名、校正方法、阈值和置换数建立断言；缺代码与代码矛盾分开判定。

## L5. 机器学习验证须以数据血缘而非图名判定

- **错误类型：** 验证集误称、信息泄漏、评估产物不完整。
- **具体表现：** 训练集交叉验证保存预测被称为验证集，特征在数据分割前筛选；无独立验证却宣称独立验证；ROC 只有图片而缺结构化指标。
- **触发场景：** caret/交叉验证、训练—测试划分、特征选择、列线图或 ROC 汇报。
- **证据依据：** CF-021、CF-022、CF-023、CF-024。
- **正确标准：** 明确样本从原始数据到 split、feature selection、fit、CV、holdout/external evaluation 的路径；CV 预测不得称为独立验证；监督特征选择必须在训练折/训练集内部完成；ROC 至少保存 AUC、CI、threshold、sensitivity、specificity、标签和数据集身份。
- **下次审核提醒：** 不凭文件名或“validation”字样判断验证层级；检查代码对象来源和样本 ID 是否真正隔离。
- **严重程度：** 验证误称或泄漏通常至少 MAJOR；单纯缺结构化导出可按影响判 WARNING。
- **可执行规则建议：** C02 强制输出 dataset-lineage 表，并对 pre-split selection、CV/holdout 混称和缺 ROC 结构化字段设置检查。

## L6. 高风险模块统一用四维矩阵，且 GraphBAN 必须显式入列

- **错误类型：** 有结论/有图片被误当成证据充分或可复现。
- **具体表现：** 本项目 docking 有主张与实现线索但缺最低证据和复现包；MD、GraphBAN 同样缺原始/数值证据与复现材料；virtual KO 缺实现、证据和身份映射。GraphBAN 又容易因未显式列入 policy 而漏审。
- **触发场景：** docking、MD、GraphBAN/深度学习虚拟筛选、virtual KO 等高风险模块。
- **证据依据：** `leader_confirmed` 高风险四维结果：docking `true,true,false,false`；MD `true,false,false,false`；GraphBAN `true,false,false,false`；virtual KO `false,false,false,true`。
- **正确标准：** 每模块独立回答“主张/实现、最低证据、可复现性、结论边界”四维；任一维不能由另一维代偿。GraphBAN 最低包须含药库来源/版本/ID、模型权重、推理配置和聚合规则。
- **下次审核提醒：** 图、表、摘要分数不等于原始输出；身份链、版本、参数、原始产物与数值序列必须可追溯。
- **严重程度：** 框架 P0；项目严重度根据报告主张和缺口影响判定，不因“没有代码”机械升级。
- **可执行规则建议：** 将 `graphban_virtual_screening` 纳入 canonical high-risk targets，并为四类模块建立统一 schema 和模块专属 minimum package。

## L7. 收敛去重必须按错误机制和修复路径，而非关键词

- **错误类型：** 语义误合并导致发现被吞并。
- **具体表现：** 数据集身份、QC 反增、细胞翻译、GraphBAN 复现、docking 证据、对接图自证、SHAP 数量和验证设计可能共享同一图号/数据集/模块关键词，但错误机制与修复动作不同。
- **触发场景：** 多 subagent findings 汇总、自动相似度聚类、同模块多证据来源。
- **证据依据：** 26YYH097F 经仲裁由 34 条规范化发现收敛为 25 条 canonical findings，且存在多组必须保持分离的相似候选。
- **正确标准：** 合并键至少包含 `module + error_mechanism + evidence_object + repair_path`；任一实质不同则默认不合并。合并必须保留来源、证据与最高严重度依据。
- **下次审核提醒：** “同一数据集”“同一张图”“同为高风险模块”都不是充分合并条件；先问是否能由同一个修复动作完整关闭。
- **严重程度：** 框架 P0；错误合并可能掩盖 CRITICAL/MAJOR 项。
- **可执行规则建议：** convergence 回归集加入负向样例；对身份错配、QC 不变量、验证泄漏、方法名错配设置禁止自动吞并标签。
