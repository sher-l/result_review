## 1. 核心发现

### 1.1 跨项目Copy-paste残留（FATAL — 最重要教训）

报告从至少两个不同项目Copy-paste了方法/结果描述，导致：

| 残留内容 | 出现次数 | 来源推测 |
|---------|---------|---------|
| "NAFLD"（非酒精性脂肪肝） | 3处 | NAFLD项目模板 |
| "LSCC"（喉鳞状细胞癌） | 1处 | LSCC项目模板 |
| "GSE89632"（NAFLD数据集） | 1处 | 与NAFLD残留同源 |

**检测方法**: 全文搜索 `NAFLD|LSCC|GSE89632` 即可定位全部5处。

**根因分析**: 
- 分析师从NAFLD项目模板复制了差异分析方法(1.2.1)和CellChat方法(1.2.12)的描述
- 从LSCC项目复制了WGCNA结果段的模板语句
- GSE89632是NAFLD相关数据集，与NAFLD残留同源
- **关键教训**：疾病名称和数据集编号是最容易在Copy-paste中遗漏替换的元素

### 1.2 UBE2L6 最佳对接位姿选择错误（CRITICAL）

- CurPockets_info.txt 显示 5 个位姿，最优为 Pose 1（-7.6 kcal/mol）
- 实际交付选择了 Pose 2（-6.9 kcal/mol）
- 结合能汇总表同步记录了错误值 -6.9
- 错误贯穿整条交付链：rawdata → result → 汇总表 → 可视化 PPT

**根因分析**: 分析人员在 5 个位姿中可能手动选择了非最优位姿，或笔误选错了 pose 编号。另一个可能原因是先运行了其他基因的对接，Pose 2 的编号看起来与其他基因的最优一致，导致惯性错误。

### 1.2 纯结果交付项目的审核适配

- 本项目无 Word/PDF 分析报告，无代码脚本
- 仅交付结构化文件（PDB/SDF/TXT/PNG/XLSX/PPTX）
- 现有框架主要面向"报告 + 代码 + 结果文件"的完整项目，需补充纯结果交付的审核路径

## 2. 新增检查规则

### 2.1 分子对接位姿选择验证（P0 — 必做）

**对接结果交付中，必须逐一验证**：
1. result 目录中选定的 PDB 文件是否对应 CurPockets_info.txt 中结合能最优的位姿
2. 结合能汇总表中的数值是否与选定位姿的分数一致
3. 若选定了非最优位姿，是否有书面理由（如活性口袋位置不合理、已知活性位点匹配）

**验证方法**：
```python
# 读取 CurPockets_info.txt，提取最优位姿
# 比对 result/ 目录中的 PDB 文件名中的 pose 编号和分数
# 比对 Excel 汇总表中的数值
```

**判定标准**：
- 选定位姿 = 最优位姿 且 汇总表数值一致 → ✅ 通过
- 选定位姿 ≠ 最优位姿 且有书面理由 → ⚠️ 部分通过
- 选定位姿 ≠ 最优位姿 且无理由 → 🔴 CRITICAL

### 2.2 纯结果交付项目审核路径

当项目仅交付结果文件（无报告、无代码）时：
1. 以交付的汇总表（如结合能.xlsx）作为"报告"进行核查
2. 以原始数据文件（如 CurPockets_info.txt）作为证据来源
3. 重点核对：汇总表数值 ↔ 原始数据 ↔ 选定结果文件 三方一致性
4. 必须标记"无分析报告"和"无代码"的双重缺失

## 4. 跨项目Copy-paste防护规则（本次新增）

### 4.1 审核时必须执行的全文搜索

```
# 疾病名称残留
搜索：NAFLD|LSCC|LIHC|LUAD|LUSC|BRCA|KIRC|GBM|AML 等常见疾病缩写
排除：与当前项目疾病一致的术语

# 数据集编号验证
搜索：GSE\d+ 
逐一确认每个GEO编号属于本项目

# 分组术语验证
搜索：Normal|Tumor|Cancer|NAFLD|Disease 等
确认与项目疾病类型匹配
```

### 4.2 Copy-paste污染的典型模式

1. **方法描述模板化复制** — 1.2.x节的方法描述最容易残留旧项目术语
2. **CellChat等模板段落** — 细胞通讯分析的方法描述几乎全段复制
3. **数据集编号跟随** — 旧项目GEO编号与旧疾病名常同时出现
4. **WGCNA结论段** — "与XX发展相关性较大"中的XX容易残留

### 4.3 判定标准

- 疾病名称残留（NAFLD/LSCC等） → 🔴 **FATAL**
- 数据集编号错误（GSE89632等） → 🔴 **CRITICAL**
- 分组术语不匹配 → 🔴 **FATAL**
