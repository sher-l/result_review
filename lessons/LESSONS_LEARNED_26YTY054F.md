# 26YTY054F 审核错题集

## 案例摘要

项目：26YTY054F。主题：多层次数据（转录组、单细胞、网络毒理）挖掘万古霉素诱导急性肾损伤关键驱动因素。审核中发现外项目编号残留、未报告数据集、图号重复、对接/MD 证据包不足与结论表述过强等问题。框架规则已同步修正：**代码/脚本未提供本身仅作为 WARNING**；若同时存在结果目录为空、正文有结果但无图件、数据源错写、外项目残留或结论与证据不匹配，则按对应事实问题独立定级。

## 错题 1：代码路径残留外项目编号

- 错误类型：跨项目复制残留 / 代码污染。
- 具体表现：当前项目为 26YTY054F，但原始数据脚本中出现 `26YTY041F/result/00_rawdata/` 路径。
- 触发场景：复用既往项目 rawdata 处理脚本、批量改编号不彻底。
- 证据依据：`script/r.00.rawdata.R` L427、L476；机械检查 MC-008。
- 正确标准：代码、路径、输出目录、报告项目编号必须一致；任何外项目编号需解释为外部数据源，否则按跨项目残留处理。
- 下次审核提醒：全文 grep 项目编号模式 `\d{2}Y[A-Z]+\d{3}F`，不要只查报告正文；脚本路径和 setwd/read/write 路径要单独核查。
- 严重程度：CRITICAL。

## 错题 2：代码引用未在报告数据源表声明的数据集

- 错误类型：数据源清单不完整 / 隐性数据集残留。
- 具体表现：代码引用 `GSE61739`，但报告数据源表列出的数据集为 `GSE30718`、`GSE139061`、`GSE183277`、`GSE227970`，未列 `GSE61739`。
- 触发场景：原始数据下载脚本从旧项目复制，或探索性数据未在最终报告数据源表更新。
- 证据依据：`script/r.00.rawdata.R` L197-L211；`report_text.txt` L13-L18；机械检查 MC-008。
- 正确标准：所有进入代码流程的数据集必须在报告数据源表、rawdata 或方法流程中有明确说明；若未参与最终分析，应从交付代码中移除或注释说明。
- 下次审核提醒：提取报告、rawdata 文件名、代码中的全部 GSE 编号做集合差异；“代码有、报告无”的数据集至少 MAJOR，若影响结论可升级。
- 严重程度：MAJOR。

## 错题 3：同一 Figure 编号跨章节复用

- 错误类型：图号重复 / 图文引用不一致。
- 具体表现：`Figure 18` 同时用于 2.16 生物标志物模拟敲除分析和 2.17 GSE227970 差异表达分析。
- 触发场景：后续章节追加图片后未统一重编号，或复制图注时遗漏空格/编号更新。
- 证据依据：`report_text.txt` L265-L272；机械检查 MC-013。
- 正确标准：同一正式报告中 Figure 编号应唯一，正文引用、图注、图片顺序需一致。
- 下次审核提醒：同时匹配 `Figure 18` 与 `Figure18` 这类空格变体；按章节统计图号唯一性。
- 严重程度：MAJOR。

## 错题 4：高风险模块“脚本未提供”只能作为 WARNING，但证据包不足和结论过强需另行判断

- 错误类型：高风险模块证据链不完整 / 严重度规则误用风险。
- 具体表现：分子对接和分子动力学正文有结果描述与图片，但交付代码中未识别到对接/MD 脚本。按更新后的框架，脚本未提供本身只记 WARNING；但若报告用“进一步证实”“稳定结合”等强结论，仍需结合参数、输入结构、原始输出、轨迹处理和数值导出判断证据是否充分。
- 触发场景：药物-靶点预测后追加对接/MD图件，结果图存在但复现材料不完整。
- 证据依据：`report_text.txt` L169-L204、L277；机械检查 MC-016；`result_review_framework/scripts/mechanical_checks.py` 已将对接/MD 未识别脚本降为 WARNING。
- 正确标准：缺脚本本身不应定为 CRITICAL；但高风险模块必须分别判定“模块存在、证据充分、可复现、结论不过度”。若结论强度超过证据，应作为独立问题定级。
- 下次审核提醒：不要把“未提供代码”直接写成阻断性 CRITICAL；也不要因为降级为 WARNING 就放过结论过度外推。脚本缺口、参数缺口、结果缺口、结论过强应拆分处置。
- 严重程度：脚本未提供为 WARNING；结论过度外推通常 MAJOR，视证据影响可调整。

## 错题 5：框架输出完成后必须执行错题集闭环

- 错误类型：审核流程收尾漏项 / lesson-bank 未更新。
- 具体表现：本次先完成了终稿、收敛、HTML 和严重度规则修正，但未第一时间写入 `lessons/LESSONS_LEARNED_26YTY054F.md` 并更新索引。
- 触发场景：用户要求快速修正规则或重出 HTML 时，容易只关注报告产物，漏掉框架要求的审核后沉淀。
- 证据依据：`result_review_framework/policy/audit_policy.json` 中 `must_update_lesson_bank_after_audit=true`；`lessons/LESSONS_LEARNED.md` 错题集更新规则。
- 正确标准：审核结束或规则调整落地后，必须记录本次典型错误点；无新增模式也要在复盘中说明无新增沉淀项。
- 下次审核提醒：最终回复前检查三项：终稿 lint、HTML、错题集索引；任一缺失不得宣称框架闭环完成。
- 严重程度：流程 WARNING。
