## 1. 核心发现

### 1.1 临床统计项目的 Copy-paste 残留（FATAL）

与生信项目类似，临床统计报告同样存在模板残留问题：
- 1.1 节数据描述初始版本完全来自其他项目
- SHAP 蜂群图图注残留"死亡风险"（生存分析模板语言）
- DCA 图注残留"不同时间结局中"（Cox 回归模板语言）

**检测方法**: 在临床统计报告中搜索生存分析特征词 `死亡|生存|时间尺度|不同时间|hazard|survival`。

### 1.2 "逐步回归"方法虚假声明（CRITICAL）

- 报告方法段和结果段均声称"采用逐步回归优化模型"
- 代码中无 `step()`、`stepAIC()`、`stepwise` 调用
- 实际做法：全模型后直接取 P<0.05 系数

**新规则**: 临床统计项目必须验证方法描述与代码中的函数调用一致。重点搜索：
- 声称"逐步回归" → 需找到 `step()` / `stepAIC()` / `stepwise()`
- 声称"LASSO筛选" → 需找到 `glmnet` / `cv.glmnet`
- 声称"VIF筛选" → 需找到 `vif()` / `car::vif`

### 1.3 基线描述方向性事实错误（CRITICAL）

- 报告写"胎数更高"，实际双胎率 4.4% vs 13.0%（方向相反）
- 报告写"人工剥离胎盘发生率更高"，实际 62.6% vs 71.3%（方向相反）

**新规则**: 基线统计表中的连续/分类变量方向性比较描述，需逐条与 baseline.csv 的实际数值核对。

## 3. 关键教训

1. **临床统计报告同样存在 Copy-paste 问题**，且更隐蔽（生存分析术语混入 Logistic 报告）
2. **方法描述必须与代码调用一一对应**，不能仅看描述是否"合理"就放行
3. **基线描述的方向性核查是临床统计特有的高频问题**，生信项目通常无此环节
4. **Bootstrap 次数是列线图审核的常见不一致点**（图件内嵌 vs 报告文字 vs 代码参数）
5. **复审时要警惕新增问题**：修改过程中可能引入新的格式错误或模板残留
