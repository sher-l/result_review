# 26YHB489F 框架优化记录

## 总体判断

v6.7 已具备视觉闭合、高风险模块最小证据、结构化 finding 和审核后学习门禁，本项目无需新增审核维度或严重度等级。需要加强的是现有规则的可执行断言、数据流传播和子任务提示词，使 raw P 入口错误、未声明数据集范围、图件自识别缺口及错误归并更早暴露。本次仅记录改进建议，未修改框架代码、政策或配置。

## Check 加强项

1. `RAW_P_DOWNSTREAM_TAINT`：解析筛选字段及后续输入文件；当 `p < α` 被用于多重比较筛选而 `p.adjust/FDR` 可用时，输出受影响的完整下游文件清单及必须重跑的边界。
2. `DATASET_SCOPE_MATRIX`：从 `report_text`、脚本读写语句、文件名、PDF/图标题反向提取所有 GEO/队列编号，按“已声明/输入已交付/进入代码/进入结果/进入正文”五态核对。
3. `FIGURE_PANEL_SELF_IDENTIFIABLE`：对 docking 等高风险多面板图要求每个面板自身包含受体、配体和与定量结论对应的分数；邻接表或 A–E 顺序不能作为唯一识别依据。
4. `VISUAL_CHECKLIST_NEAREST_CAPTION`：清单生成器按最近的后置 Figure 标题重新归组，防止 `image_018/019`、`image_026/027` 沿用上一图号。
5. `PRODUCER_CONSUMER_FILENAME_ASSERTION`：联检脚本写出名和读取名；检测下划线/点号等仅字符差异并要求文件存在断言，对应 `AF-027`。
6. `CONVERGENCE_SEMANTIC_GUARD`：以“证据对象、主张、失效机制、修复动作”四元组决定是否归并；禁止仅因共享数字或同一章节合并，例如本项目 M001–M003 均应保持拆分。

## Subagent prompt 加强项

- A 路交付证据切片：固定输出数据集范围矩阵，并打开交付 PDF/结构化表核对面板标题，区分未声明分支是否实际进入交付结果。
- B 路视觉切片：必须逐张给出 `needs_audit=true` 的 AI 目视结论和计数闭合；0 machine flag 不得直接通过；docking 面板增加自识别字段检查；清单图号必须与 `report_text` 最近图注二次核对。
- C 路代码/统计切片：从筛选语句追踪到富集、交集、网络和后续表达输入；同时报告 raw P 与 adjusted P 命中数、靶基因排除后的集合及下游污染边界。
- 收敛/仲裁切片：错误阈值、文字损坏、伪重复、文件名断链分别判断，不因共享“37”“128”或同属一模块而误并；对重跑未知量不得推断结果；将其转换为可执行、可验证的客观完成门槛并在仲裁中 closed，不得因结果未知而保留为裁决未决。

## No-op 判断

1. 不把 standard lane 改为 79 张全部逐图必审。现有策略已要求高风险/机器命中图进入 AI 目视，本项目 15/15 已闭合；其余 64 张有明确豁免规则和计数，问题在执行记录而非通道设计。
2. 不新增严重度等级或审核维度。`AF-026` 可由 D5 与现有 CRITICAL 标准表达；docking/MD、数据集范围和视觉自识别也已能落入 D1–D6。
3. 不将“代码中出现未声明数据集”自动等同为报告结论污染。GSE39055 已进入交付结果，GSE16091 仅确认活跃分支且未见最终图表，二者必须分别陈述。
4. 不把“按 FDR 重跑”解释为“结果必然为零”。当前结果链不能沿用已经成立，但新条目数须由重跑后的结构化输出决定。
5. 不把 Figure 13 自识别缺口与 docking 复现参数缺口或计算候选外推合并；`AF-015`、`AF-009`、`AF-028` 的对象和修复路径不同。

- raw P 与 adjusted P 集合相同、部分不同、全部不同三类案例，验证下游传播范围和“不得预断为零”。

- docking 五面板有邻接表但面板内无实体标签的案例应命中 WARNING；面板标题完整时应通过。
